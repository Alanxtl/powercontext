### 1.5 「测试未通过 → 回灌反馈 → 再改」的机制

模块在写入修改后立即运行 `pytest -q tests`；若未通过，把失败日志作为「反馈」连同上下文再次发给
MiniMax（最多 `SDD_MAX_ROUNDS=3` 轮）。本次运行第一轮即通过（`rounds: [("round1", 0)]`），
因此没有触发第二轮；该机制保留在代码中（`sdd_context/cli.py` 的 `command_demo` 循环），
并在 `evidence/patches/` 与 `evidence/tests/` 中按轮次分别留档。

> 开发过程中确实出现过一轮失败：当时的规格里「忽略大小写」与测试期望值不一致，
> 模块把失败信息回灌后由 MiniMax 修正。该问题在规格澄清后已修正，最终提交的测试集
> 与代码差异是同一次运行的产物。

## 2. seekdb 查询记录

### 2.1 存储内容

同一个嵌入式 seekdb 实例（数据目录 `minimax/.state/seekdb/`）里同时存放：

| 表 | 内容 | 规模 |
| --- | --- | --- |
| `sdd_spec` | 规格条目（标识、标题、状态、适用范围、全文） | 6 行 |
| `sdd_code_symbol` | 代码符号（路径、限定名、行范围、签名、文档、片段） | 11 行 |
| `sdd_test_case` | 测试用例（路径、名称、函数体） | 15 行 |
| `sdd_document` | 完整文件内容 | 6 行 |
| `sdd_query_log` | 每次检索的 SQL、参数、命中行数、耗时 | 本次 50 条 |
| `pc_*`（PowerContext 自建） | Scope、Source、Artifact、Work 记录等 | — |

### 2.2 构造上下文时实际执行的查询

留档：`evidence/db/queries-20261028T045313Z.json`（`python -m sdd_context queries` 可随时导出）。
一次上下文构造共执行 6 类查询（下列行数为一次调用的实测值）：

| 目的 | SQL 形态 | 命中行数 |
| --- | --- | ---: |
| `select-specifications` | `SELECT ... FROM sdd_spec WHERE MATCH(content) AGAINST (:match IN BOOLEAN MODE) ORDER BY score DESC LIMIT :limit` | 6 |
| `select-code-symbols` | 同上，作用于 `sdd_code_symbol` | 8 |
| `select-test-cases` | 同上，作用于 `sdd_test_case` | 8 |
| `find-code-symbols` | `SELECT ... FROM sdd_code_symbol WHERE name IN (:name_0, ...)`（规格里引用的符号反查） | 1 |
| `find-related-tests` | `SELECT ... FROM sdd_test_case WHERE content LIKE :name_0 OR ...`（提到该符号的测试） | 15 |
| `fetch-documents` | `SELECT ... FROM sdd_document WHERE path IN (:path_0, ...)`（选中符号所在文件的完整内容） | 3 |

这些查询的**结果**直接决定了进入上下文的规格条目、代码符号、完整文件与测试清单——
上下文里「来源清单」的每一行都能追溯到上面某一条查询的命中行。

## 4. 「规格更新后上下文随之变化」的校验

命令：`python minimax/scripts/verify_spec_update.py`（随提交物提供，可复跑）

做法：给 `workspace/spec/SPEC-FILTER-001.md` 追加一条带标记的新条款 → 重新 `import` →
生成上下文 → 断言上下文包含新条款；随后还原规格、再次 `import` → 断言上下文恢复原样。

留档：`evidence/verification/spec-update-check.json`，本机实测：

```json
{
  "with_updated_spec":    { "import_exit_code": 0, "contains_marker": true,  "contains_original_line": true },
  "after_reverting_spec": { "import_exit_code": 0, "contains_marker": false, "contains_original_line": true },
  "passed": true
}
```

这说明上下文来自实际存储的规格材料（seekdb 语料表在 `import` 时按最新文件内容重建），
而不是固定答案。
