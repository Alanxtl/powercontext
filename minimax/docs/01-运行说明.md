# 运行说明

本目录是一个自包含的提交物：从干净环境开始，按本文档即可初始化数据、启动模块并执行验证样例。

## 1. 环境要求

| 项目 | 要求 | 本次验证环境 |
| --- | --- | --- |
| 操作系统 | Linux x86_64（官方验证口径）；macOS 可用 | Windows 11 x64（已实测通过，见「已知限制」） |
| Python | 3.11 – 3.13 | CPython 3.11.2 |
| 包管理 | `uv`（或 `pip`） | uv 0.12.3 |
| 外部服务 | 不需要（seekdb 以嵌入式实例运行在本机） | — |

需要联网的只有两处：安装 Python 依赖、调用 MiniMax 模型 API。

## 2. 安装依赖

```bash
cd minimax
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -e .
```

`powercontext[seekdb]` 这个 extra 只在 Linux / macOS 上会自动带上 `pylibseekdb`。
在 Windows 上需要手动补装（PyPI 提供 `win_amd64` wheel）：

```powershell
uv pip install --python .venv\Scripts\python.exe pylibseekdb
```

依赖清单（本次实测版本）：

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| `powercontext` | 1.4.1 | 任务状态与工程资料的持久化、读回 |
| `pylibseekdb` | 1.4.0.post2 | 嵌入式 seekdb 实例 |
| `httpx` | 0.28.x | 调用 MiniMax HTTP API |
| `pytest` | 9.x | 运行业务工程的目标测试与回归测试 |

## 3. 配置

所有配置都通过环境变量给出，代码里没有任何写死的凭据：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MINIMAX_API_KEY` | 无（必填） | MiniMax API Key |
| `MINIMAX_BASE_URL` | `https://api.minimax.io/v1` | MiniMax 接口地址；官方开放平台用 OpenAI 兼容协议，`agent.minimax.cn` 网关用 Anthropic Messages 协议 |
| `MINIMAX_MODEL` | `MiniMax-M3.1-Flash` | 模型 id，需与账号实际可用的模型一致 |
| `MINIMAX_PROTOCOL` | `auto` | `auto` / `anthropic` / `chat-completions`，`auto` 按 `MINIMAX_BASE_URL` 判断 |
| `MINIMAX_TIMEOUT_SECONDS` | `180` | 单次请求超时 |
| `MINIMAX_MAX_TOKENS` | `8192` | 单次请求最大输出 token |
| `SDD_WORKSPACE` | `minimax/workspace` | 被修改的业务工程根目录 |
| `SDD_STATE_DIR` | `minimax/.state` | 嵌入式 seekdb 数据目录（语料库 + 任务状态） |
| `SDD_EVIDENCE_DIR` | `minimax/evidence` | 运行产物目录 |
| `SDD_DATABASE` | `seekdb` | PowerContext 使用的后端，可选 `sqlite` |
| `SDD_SCOPE_KEY` | `sdd-context-taskboard` | PowerContext Scope 的幂等键 |
| `SDD_SPEC_LIMIT` / `SDD_CODE_LIMIT` / `SDD_TEST_LIMIT` | `8` / `8` / `8` | 上下文里各类来源的条数上限 |
| `SDD_CONTEXT_MAX_BYTES` | `24000` | 上下文字节预算 |
| `SDD_MAX_ROUNDS` | `3` | 测试未通过时最多让 MiniMax 修复几轮 |

示例（Linux / macOS）：

```bash
export MINIMAX_API_KEY=<你的 Key>
export MINIMAX_BASE_URL=https://api.minimax.io/v1
export MINIMAX_MODEL=MiniMax-M3.1-Flash
```

## 4. 调用入口

入口是一个命令行工具 `python -m sdd_context`（安装后也可用 `sdd-context`）。每个子命令的输入输出：

| 命令 | 输入 | 输出 |
| --- | --- | --- |
| `import` | 工作区目录（默认 `workspace/`） | 规格 / 代码符号 / 测试写入 seekdb 语料表；同时作为 Source 存入 PowerContext。输出导入计数与 Scope id |
| `context --task "<任务>"` | 任务描述 | 组装好的开发上下文（Markdown）+ 来源清单 + 本次执行的数据库查询记录 |
| `plan --task "<任务>" [--apply] [--feedback-file <日志>]` | 任务描述（可选测试失败反馈） | MiniMax 的修改结果、代码差异（`.patch`）、请求与响应记录（`evidence/minimax/*.json`）。带 `--apply` 时写入工作区 |
| `test [--label <名称>]` | 无 | 运行 `pytest -q tests`，记录退出码与日志 |
| `state save --task "<任务>" ...` | 任务标识与进展 | 任务状态写入 PowerContext，输出状态 Source id |
| `state load --task "<任务>"` | 任务标识 | 读回任务状态与工作连续性视图 |
| `resume --task "<任务>"` | 任务标识 | **新进程**读回状态并继续使用（模块重启后的复用演示） |
| `queries` | 无 | 输出 seekdb 中记录的全部查询（数据库使用证据） |
| `snapshot --label <名称>` / `reset --label <名称>` | 标签 | 工作区文件快照 / 从快照恢复（验证样例的重置方法） |
| `demo` | 可选 `--task` | 一键跑完整闭环，产物写入 `evidence/demo/` |

## 5. 执行验证样例

```bash
cd minimax
bash scripts/run_demo.sh
# Windows
powershell -ExecutionPolicy Bypass -File scripts\run_demo.ps1
```

`demo` 会依次完成：

1. `import`：导入规格 / 代码 / 测试到 seekdb 与 PowerContext；
2. 快照工作区（`evidence/snapshots/before`），运行测试，得到「修改前」结果；
3. `context`：检索并组装开发上下文；
4. `plan --apply`：把上下文交给 MiniMax 产出修改并写入工作区，然后运行测试；
   若测试未通过，把失败日志回灌给 MiniMax 继续修复（最多 `SDD_MAX_ROUNDS` 轮）；
5. `state save`：把任务进展与验证结果写入 PowerContext；
6. `resume`：以**独立子进程**重新启动模块，读回状态并继续使用。

## 6. 数据与产物的位置

| 目录 | 内容 |
| --- | --- |
| `minimax/.state/seekdb/` | 嵌入式 seekdb 数据目录：PowerContext 的 `pc_*` 表 + 本模块的 `sdd_*` 语料表与 `sdd_query_log` 查询日志 |
| `minimax/evidence/import/` | 导入记录 |
| `minimax/evidence/context/` | 上下文 Markdown 与 JSON（含数据库查询记录） |
| `minimax/evidence/minimax/` | MiniMax 请求与响应原文 |
| `minimax/evidence/patches/`、`evidence/diff/` | MiniMax 产出的修改与 unified diff |
| `minimax/evidence/tests/` | 修改前 / 各轮的 pytest 日志与退出码 |
| `minimax/evidence/demo/` | 一次完整闭环的汇总 |
| `minimax/evidence/snapshots/` | 工作区快照（用于重置） |

## 7. 重置

```bash
python -m sdd_context reset --label before   # 恢复业务工程到修改前
rm -rf .state evidence                        # 清空数据库与全部运行产物
```

`demo` 每次都会先做一次 `before` 快照，因此重置不依赖版本控制。

## 8. 已知限制

1. **嵌入式 seekdb 的官方验证平台是 Linux / macOS**：`pylibseekdb` 在这两个平台随
   `powercontext[seekdb]` 自动安装。Windows 需要手动安装 wheel；本模块已在 Windows 11 +
   `pylibseekdb 1.4.0.post2` 上实测通过（语料表、FULLTEXT 检索、跨进程持久化均正常），
   但官方口径仍以 Linux 为准。
2. **符号抽取使用 Python 标准库 `ast`**，因此只对 Python 工程有效；其它语言工程需要替换
   `sdd_context/workspace.py` 的抽取实现（PowerContext 自带的原生代码索引依赖 POSIX 文件锁，
   在 Windows 上不可用，故本模块未采用）。
3. **上下文是检索式选择**：规格条目很多或任务描述过于抽象时可能漏选，需要调大
   `SDD_SPEC_LIMIT` 等上限，或在任务描述中写明涉及的文件 / 符号名。
4. **MiniMax 模型 id 与账号绑定**：`MINIMAX_MODEL` 需要填写账号实际可用的模型，
   否则请求会返回 401 / 404。
5. 模块只写入 `SDD_WORKSPACE` 内的文件，越界路径会被拒绝；模型也不会被允许修改测试文件
   （该约束写在给模型的提示词里，模块本身不强制）。
