# 验证样例

本样例用于核对题面要求的六项验收内容（能够运行、MiniMax 实际参与、上下文正确、数据库实际参与、
状态能够复用、代码修改有效）。所有数字来自本机实测，日志路径见每一节末尾。

## 1. 任务描述

> 为任务列表增加按负责人过滤能力，并保持既有排序与状态过滤行为不变。

被修改的业务工程是 `minimax/workspace/`（taskboard）：一个内存任务看板服务，
`TaskBoardService.list_tasks` 支持按状态过滤、按优先级排序与条数限制，**尚不支持按负责人过滤**。

## 2. 有效的规格条目

导入到 seekdb 的规格（`workspace/spec/`，每条一个文件，格式：标识 / 状态 / 适用范围 / 需求 / 不变量 / 验收要点）：

| 标识 | 标题 | 状态 | 适用范围 | 与本次任务的关系 |
| --- | --- | --- | --- | --- |
| `SPEC-CORE-001` | 任务列表默认排序 | 生效 | `TaskBoardService.list_tasks` | 必须保持不变 |
| `SPEC-CORE-002` | 任务状态过滤 | 生效 | `TaskBoardService.list_tasks` | 必须保持不变 |
| `SPEC-CORE-003` | 结果条数限制 | 生效 | `TaskBoardService.list_tasks` | 必须保持不变 |
| `SPEC-FILTER-001` | 按负责人过滤 | 待实现 | `TaskBoardService.list_tasks` | **本次要实现** |
| `SPEC-FILTER-002` | 空白负责人输入的边界行为 | 待实现 | `TaskBoardService.list_tasks` | **本次要实现** |
| `SPEC-FILTER-003` | 负责人过滤与其它过滤条件组合 | 待实现 | `TaskBoardService.list_tasks` | **本次要实现** |

关键边界（`SPEC-FILTER-001` / `SPEC-FILTER-002`）：

- 比较忽略大小写，比较前去除输入两端空白；
- 未指派（`assignee is None`）的任务不出现在任何具体负责人的过滤结果中；
- `assignee` 传入空串或纯空白时，视为「未指定过滤」，返回全部任务。

## 4. 操作步骤

### 4.1 一键执行

```bash
cd minimax
export MINIMAX_API_KEY=<你的 Key>
bash scripts/run_demo.sh
```

### 4.2 分步执行（与一键脚本等价）

```bash
cd minimax
export PYTHONPATH="$PWD"

# 1) 导入规格、代码、测试到 seekdb 语料库，并作为 Source 存入 PowerContext
python -m sdd_context import

# 2) 快照工作区（重置用）并运行测试 —— 得到「修改前」结果
python -m sdd_context snapshot --label before
python -m sdd_context test --label before

# 3) 生成开发上下文：适用规格 + 需要修改的代码 + 验证测试 + 任务状态
python -m sdd_context context --task "为任务列表增加按负责人过滤能力，并保持既有排序与状态过滤行为不变"

# 4) 把上下文交给 MiniMax 产出修改并写入工作区
python -m sdd_context plan --task "为任务列表增加按负责人过滤能力，并保持既有排序与状态过滤行为不变" --apply

# 5) 运行测试（修改后）
python -m sdd_context test --label after

# 6) 保存任务状态到 PowerContext
python -m sdd_context state save --task "为任务列表增加按负责人过滤能力，并保持既有排序与状态过滤行为不变" \
    --completed "导入规格、代码与测试资料" "由 MiniMax 完成代码修改" \
    --todo "" \
    --result "修改前目标测试失败、修改后目标测试与回归测试全部通过" \
    --status succeeded

# 7) 重启模块，读回并使用状态
python -m sdd_context resume --task "为任务列表增加按负责人过滤能力，并保持既有排序与状态过滤行为不变"

# 附：查看数据库查询记录
python -m sdd_context queries

# 附：校验「规格更新后上下文随之变化」
python scripts/verify_spec_update.py
```

### 4.3 规格更新校验（对应验收项「上下文正确」）

`scripts/verify_spec_update.py` 会：

1. 在 `workspace/spec/SPEC-FILTER-001.md` 里追加一句带标记的新条款；
2. 重新 `import` 并生成上下文，断言上下文里出现新条款、且旧条款仍在；
3. 还原该规格，再次 `import` 并生成上下文，断言上下文不再出现新标记、旧条款恢复；
4. 把结论写入 `evidence/verification/spec-update-check.json`。

本机实测结果（`passed: true`）：

```json
{
  "with_updated_spec":  { "contains_marker": true,  "contains_original_line": true },
  "after_reverting_spec": { "contains_marker": false, "contains_original_line": true }
}
```

说明模块的输出来自实际存储的材料，而不是固定答案。

## 6. 上下文中必须包含的来源（便于审核核对）

| 类别 | 必须包含 |
| --- | --- |
| 规格 | `SPEC-FILTER-001`、`SPEC-FILTER-002`、`SPEC-FILTER-003`（本次要实现）以及 `SPEC-CORE-001`、`SPEC-CORE-002`、`SPEC-CORE-003`（必须保持的行为） |
| 代码 | `src/taskboard/service.py` 中的 `TaskBoardService.list_tasks` 及其所在文件的完整内容 |
| 测试 | `tests/test_assignee_filter.py`（目标功能测试）与 `tests/test_taskboard.py`（回归测试） |

这些来源不是写死的：`context` 命令每次都重新用 seekdb 全文检索 + 规格↔符号引用解析来选择。
修改 `workspace/spec/` 中的规格并重新 `import` 后，`context` 的输出会随之改变。

## 7. 重置方法

```bash
python -m sdd_context reset --label before   # 业务工程恢复到修改前
rm -rf .state evidence                        # 清空数据库与全部运行产物（可从零重跑）
```

`demo` 在每次开始时都会生成 `evidence/snapshots/before` 快照，因此重置不依赖版本控制；
若要同时回到「规格未导入」的初始状态，删除 `.state/` 即可（下次 `import` 会重建语料库）。
